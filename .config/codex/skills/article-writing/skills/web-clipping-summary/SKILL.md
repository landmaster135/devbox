# Web Clipping

## 実行手順

1. 入力情報を確認する。
2. ユーザーから提供されていなければ、次の2点を必ず質問する。
  - 記事URL
  - 出力ディレクトリ
3. Web検索とページ取得で記事本文を収集する。
4. 記事内容を読み取り、`Thinking Lens` に沿って要点を整理する。
5. `web_clipper` の `patch_markdown` ツールを実行し、指定ディレクトリに新規Markdownファイルを作成し、要約を出力する（`target_title`/`target_url`/`src_markdown_content`/`out_file_path`/`top_heading_level=2` を指定）。
6. `patch_markdown` が失敗した場合は、エラー内容をそのまま報告し、`out_file_path` などの入力値修正を確認して再実行する。`patch_markdown` 以外のツールで代替作成してはいけない。
7. 出力前に「構成・言語・表の扱い・固有名詞説明・記事リンク挿入」を検証する。

## Thinking Lens

### Premise

Web上の情報は流動的であり、すべてを記憶し続けるのは難しい。新しい用語・技術・手段・考え方・事実関係を記録して後で見返せる形にし、記憶定着と知識獲得に活用する。

### Purpose

Web記事の要約を作成する。図や表、アノテーションも活用し、後で見返しやすい資料にする。

### Constraint

- 記事内容はWeb検索で取得する。
- 出力は必ず `heading 2` から書き始める。
- 要約内容は1つの `heading 2` の配下に集約する。
- `heading 3` を5つ以上含める。
- 日本語で出力する。
- 各 `heading 3` に記事中の固有名詞を含める。
- 各固有名詞に簡潔な説明を付ける。
- 記事内のテーブルや表やコードブロックは文章に言い換えず、可能な限りそのまま流用する。

## 出力フォーマット

以下の型を使う。`##` は1つのみ使用する。

```md
## <記事タイトル> 要約

### <見出し1: 固有名詞を含める>
- <固有名詞>: <簡潔な説明>

<要約>

...記事内のテーブルや表やコードブロックを流用...

### <見出し2: 固有名詞を含める>
- <固有名詞>: <簡潔な説明>

<要約>

...記事内のテーブルや表やコードブロックを流用...

### <見出し3: 固有名詞を含める>
- <固有名詞>: <簡潔な説明>

<要約>

...記事内のテーブルや表やコードブロックを流用...

### <見出し4: 固有名詞を含める>
- <固有名詞>: <簡潔な説明>

<要約>

...記事内のテーブルや表やコードブロックを流用...

### <見出し5: 固有名詞を含める>
- <固有名詞>: <簡潔な説明>

<要約>

...記事内のテーブルや表やコードブロックを流用...

```

## ファイル作成ルール

- 新規ファイルとして保存する。
- 保存先はユーザー指定の出力ディレクトリを使う。
- ファイル作成・更新は `web_clipper.patch_markdown` のみを使用する。`patch_markdown` 以外のツールでのファイル作成・更新・移動・コピー・リネームは禁止。
- ファイル名は再利用しやすい形式にする。
  - 例: `web-summary-YYYYMMDD-hhmmss-<slug>.md`
  - 日付が指定されていたら、その日付と、シェルで `date '+%H%M%S'` で現在時刻を取得してから使用する。
  - 指定されていない場合は、現在日時を使用する。
  - slugは記事タイトルから生成する。

## 最終チェック

- `##` から開始しているか。
- `##` が1つだけか。
- `###` が5つ以上あるか。
- 各 `###` に固有名詞とその説明があるか。
- 日本語で書かれているか。
- 表を文章化せずに流用しているか。
- 指定ディレクトリへ新規ファイルを書き出しているか。
