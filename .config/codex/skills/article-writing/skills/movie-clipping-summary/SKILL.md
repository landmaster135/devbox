# Movie Clipping

## 実行手順

1. 入力情報を確認する。
2. ユーザーから提供されていなければ、次の2点を必ず質問する。
  - 字幕ファイルのパス
  - 出力ディレクトリ
3. 字幕ファイルを読み取り、動画URLの記載有無を確認する。
4. 字幕ファイル内に動画URLが無ければ、動画URLを質問する。
5. 字幕内容を読み取り、`Thinking Lens` に沿って要点を整理する。
6. `web_clipper` の `patch_markdown` ツールを実行し、指定ディレクトリに新規Markdownファイルを作成し、要約を出力する（`target_title`/`target_url`/`src_markdown_content`/`out_file_path`/`top_heading_level=2` を指定）。
7. `patch_markdown` が失敗した場合は、エラー内容をそのまま報告し、`out_file_path` などの入力値修正を確認して再実行する。`patch_markdown` 以外のツールで代替作成してはいけない。
8. 出力前に「構成・言語・比較箇所の表化・固有名詞説明・動画リンク挿入」を検証する。

## Thinking Lens

### Premise

常日頃、Web上で見聞きする情報は流動的であり、それらの情報を全て記憶しておくことは至難の業である。しかしながら、なるべく今まで見聞きしたWeb記事の内容を覚えておきたいので、新しい用語、技術、手段、考え方や事実関係を記録しておくことで、後でその記録を見返すことで情報の記憶への定着を図る。また、AIが新たな知識を獲得するための手段としても、そのWeb記事の記録を役立てたい。

### Purpose

Web記事の要約を作成する。図や表、アノテーションも活用しながら、後で見返しやすい資料を作ることを心掛ける。

### Constraint

- 1つの見出し（`heading 2`）の中に要約した内容を全て記載する。
- 必ず `heading 2` から書き始める。
- `heading 3` を5つ以上記載する。
- 日本語で出力する。
- 字幕の中に出てくる数種類の固有名詞を、それぞれの `heading 3` の中に含める。
- 固有名詞に対する簡潔な説明を含める。
- 比較している部分は文章ではなくテーブル形式でまとめる。

## 出力フォーマット

以下の型を使う。`##` は1つのみ使用する。

```md
## <動画タイトル> 要約

### <見出し1: 固有名詞を含める>
- <固有名詞>: <簡潔な説明>

<要約>

...テーブルや表...

### <見出し2: 固有名詞を含める>
- <固有名詞>: <簡潔な説明>

<要約>

...テーブルや表...

### <見出し3: 固有名詞を含める>
- <固有名詞>: <簡潔な説明>

<要約>

...テーブルや表...

### <見出し4: 固有名詞を含める>
- <固有名詞>: <簡潔な説明>

<要約>

...テーブルや表...

### <見出し5: 固有名詞を含める>
- <固有名詞>: <簡潔な説明>

<要約>

...テーブルや表...
```

## ファイル作成ルール

- 新規ファイルとして保存する。
- 保存先はユーザー指定の出力ディレクトリを使う。
- ファイル作成・更新は `web_clipper.patch_markdown` のみを使用する。`patch_markdown` 以外のツールでのファイル作成・更新・移動・コピー・リネームは禁止。
- ファイル名は再利用しやすい形式にする。
  - 例: `movie-summary-YYYYMMDD-hhmmss-<slug>.md`
  - 日付が指定されていたらその日付と現在時間を使用し、指定されていない場合は現在日時を使用する。
  - slugは記事タイトルから生成する。

## 最終チェック

- `##` から開始しているか。
- `##` が1つだけか。
- `###` が5つ以上あるか。
- 各 `###` に固有名詞とその説明があるか。
- 日本語で書かれているか。
- 比較箇所をテーブルで表現しているか。
- `patch_markdown` により動画リンクが挿入されているか。
- 指定ディレクトリへ新規ファイルを書き出しているか。
